## 2. 디자인 결정 사항 (조사 반영)

1. **이원화 구조**: 탑다운 운영(리듬) + POV 제조(깊이) — 두 모드가 페이스를 교차
2. **부분 점수제**: 계량 오차·기법·시간을 항목별로 채점, 무엇이 틀렸는지 피드백. 즉시 실패 없음
3. **인내심 게이지 → 팁 배율 연동**: 제조가 느리면 팁 감소
4. **발주 루프**: 손님이 미보유 메뉴를 주문(팁 없음) → 다음 발주 동기 부여
5. **셰이킹 대체 입력**: 가속도계 불가 상황(지하철·접근성·데스크톱)을 위한 연타/드래그 폴백 필수
6. **붓기**: 길게 누르기+게이지(캐주얼 안전). 자이로 프리 푸어는 고급 옵션(post-MVP)
7. **광고**: 판 단위 강제 광고 금지(이 장르 부정 리뷰 1위 원인)
8. **주의**: 음주 소재 → 스토어 연령 등급(17+ 가능성) 확인 필요

## 3. 기술 스택 조사 요약

| 스택 | 평가 |
|---|---|
| **Phaser 3 + TS + Capacitor** ✅ 채택 | 100% 코드 기반, 웹 즉시 프리뷰(클라우드 개발·플레이테스트 공유에 최적), Capacitor 공식 Play Store 배포 경로. 캐주얼 2D라 WebView 성능세 무시 가능. 셰이크는 DeviceMotion API(Android WebView는 권한 팝업 없음) |
| **Flutter + Flame** (차선) | 네이티브 성능·모바일 배포 파이프라인 우수. 단 이 저장소의 클라우드 개발 환경에 Flutter SDK 부재(설치 ~3GB), 웹 프리뷰 공유가 상대적으로 번거로움. 성능 병목이 확인되면 이관 후보 |
| Godot 4 | 에디터 중심 워크플로 — CLI-only 환경과 마찰 |
| Unity | GUI 에디터 의존 절대적, 2D 캐주얼에 과잉 |
| React Native | 게임 엔진 부재 |
